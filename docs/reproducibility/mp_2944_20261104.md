# MP database processing and mBJ replay: recipient handoff

This guide separates three reproducibility targets. The repository contains
software; external datasets/results remain outside Git. Pin a reviewed commit,
not just `ss-screen==1.0`. A PR does not change the default branch until merged.

## 1. What to give the recipient

| Recipient's objective | Required external assets | Expected check |
|---|---|---|
| Replay existing mBJ results and pairing | `mp-2944-mbj-results-20261104.zip` | 2944 records, 1999 success / 620 not_converged / 325 failed; 318 pairs, 317 endpoints |
| Start from the MP database and reproduce screening/task export | Exact `default.db` snapshot, `mp-offline-dependencies-20261103` reader supplement, `mp-2944-reproduction-files-20261103` protocol supplement | 949 binary + 1995 ternary material tasks; compare IDs, not just counts |
| Run both stages end to end | Both rows above | Same final material membership, then independent strict mBJ replay |
| Continue alloy stability calculations | Above outputs plus the exact MACE checkpoint and the MLP environment | Separately recorded random-alloy/relaxation/mixing/phonon/hull results |

An MP ZIP is only a transport container. It must contain the specified SQLite
snapshot, not a different API export with the same filename. The database is
2,220,736,512 bytes. The mBJ replay ZIP is 11,283,960 bytes (~10.76 MiB).
Hashes and asset roles are in [mp_2944_assets.json](mp_2944_assets.json).

For the easiest first handoff, supply **the reviewed code + environment guide +
mBJ replay ZIP**. Add the database, reader and historical protocol supplements
when the recipient needs to rerun the original screening rather than replay its
results. The ~6 MB pending task bundle is an optional reference for comparing
newly exported tasks; it is not a replacement for the actual mBJ results.

Deliver databases, ZIPs, wheels and model weights through the project's agreed
artifact/file-sharing channel, with checksums and applicable provenance/licenses.
Do not commit virtual environments, credentials, POTCAR files, or full scientific
outputs. The model's distribution conditions must be checked before sharing the
weight itself; its provenance is in [models/README.md](../../models/README.md).

## 2. Environments and folder layout

Use the [three separate observed environments](../../requirements/reproduction-20261104/README.md).
Linux/WSL Python 3.11 is the validated calculation platform. Windows GUI is optional.

Set paths to the recipient's machine; keep all data and outputs outside the checkout:

```bash
export REPO='/path/to/ss-screen'
export ASSETS='/path/to/shared-assets'
export RUN='/path/to/new-mp-screen-run'
export DEPENDENCY_PACK="$ASSETS/mp-offline-dependencies-20261103"
export PROTOCOL="$ASSETS/mp-2944-reproduction-files-20261103"
cd "$REPO"
source .venv/bin/activate
python -m pip check
git rev-parse HEAD
(cd "$DEPENDENCY_PACK" && sha256sum -c SHA256SUMS)
(cd "$PROTOCOL" && sha256sum -c SHA256SUMS)
sha256sum "$ASSETS/mp/default.db"
```

The expected database SHA is
`d54bca48d1e00bdfd8db7c1e5a7b5844ccb755b948335930f09fe85444a7ebb8`.
The supplementary reader wheels target CPython 3.11 Linux x86_64; they do not
include all scientific dependencies. Do not blindly run an arbitrary downloaded
pickle or script: use the agreed, checksum-verified assets.

## 3. Fast route: strict replay of the existing mBJ results

Verify the ZIP SHA:
`3904ee370a24d7df22d692c42c4b912fb862af1ede37d4452e7e2df4b49775da`.
Extract it outside the repository and read its README and `replay_results.py`.
Then, in the screening environment:

```bash
cd "$REPO"
source .venv/bin/activate
export BUNDLE="$ASSETS/mp-2944-mbj-results-20261104"
python "$BUNDLE/replay_results.py" --bundle "$BUNDLE" --output "$RUN/mbj_replay"
```

The replay output directory must not already exist. The script verifies the
member checksums, actual calculation task/structure identities, six method
metadata batches and successful-result QC; it then validates, backfills and pairs.
It needs neither the original MP database nor VASP/AiiDA. It does not recompute
electronic band gaps. The original XML files are optional for auditing/reparsing,
not required for this parsed-result replay. The lightweight ZIP does not contain
POTCAR or the original XML files.

Acceptance: 2944 unique records, zero rejected/missing rows, 1999 successful gap
values, 620 unconverged and 325 failed records retained; 79 binary + 239 ternary
unique pairs, 317 unique endpoints. Failure/unknown values must not become zero
or be replaced with database PBE values.

The formal method is `vasp651-mbj-mpgeom-spin2-nosoc-k020-enc650-v1`.
Do not substitute it into newly exported `external-method-pending-v1` tasks by
rewriting IDs. Preserve both sets and make a separate audited mapping if needed.

## 4. Database route: the actual screening protocol

This run used a frozen canonical environment-matching snapshot and four explicit
historical exclusions. Generic CLI defaults alone are **not** the complete
historical protocol. The protocol supplement includes the MIT-licensed snapshot,
`match_audit.py`, the exclusion list and SHA256SUMS. Keep these as input provenance;
do not overwrite `src/ssscreen/pair/envmatch.py` with the snapshot.

Start with a new `RUN` directory:

```bash
mkdir -p "$RUN/01_dataset" "$RUN/02_composition" "$RUN/03_condensation/retry-01/condensed" "$RUN/05_gap_preparation"
ss-screen dataset mp --backend offline --offline-db "$ASSETS/mp/default.db" \
  --max-e-hull 0.01 --output "$RUN/01_dataset/mp.df"
ss-screen composition-screen --df "$RUN/01_dataset/mp.df" --nelems 2 \
  --max-bandgap 1.0 --max-e-hull 0.0 --min-group-size 2 --min-x-elements 2 \
  --output "$RUN/02_composition/binary_candidates.csv" --summary "$RUN/02_composition/binary_summary.json"
ss-screen composition-screen --df "$RUN/01_dataset/mp.df" --nelems 3 \
  --max-bandgap 1.0 --max-e-hull 0.0 --min-group-size 2 --min-x-elements 2 \
  --output "$RUN/02_composition/ternary_candidates.csv" --summary "$RUN/02_composition/ternary_summary.json"
cp -R "$PROTOCOL/05_gap_preparation/." "$RUN/05_gap_preparation/"
python - <<'PY'
import json, os
from pathlib import Path
import pandas as pd
r = Path(os.environ['RUN'])
df = pd.read_pickle(r/'01_dataset/mp.df')
ids = set()
for branch in ('binary','ternary'):
    ids.update(pd.read_csv(r/f'02_composition/{branch}_candidates.csv').material_id)
excluded = set(json.loads((r/'05_gap_preparation/excluded_materials.json').read_text())['material_ids'])
assert len(df)==46675 and len(ids)==4948 and excluded <= ids
assert excluded == {'mp-1205290','mp-1208530','mp-568220','mp-574458'}
df.loc[sorted(ids)].to_pickle(r/'03_condensation/candidate_materials.df')
df.loc[sorted(ids-excluded)].to_pickle(r/'03_condensation/describable_materials.df')
PY
ss-screen condense --df "$RUN/03_condensation/describable_materials.df" \
  --output-dir "$RUN/03_condensation/condensed" \
  --manifest "$RUN/03_condensation/attempts.jsonl" --index "$RUN/03_condensation/index.csv"
ss-screen condense-validate --condensed-dir "$RUN/03_condensation/condensed" \
  --output "$RUN/03_condensation/validation.csv"
PYTHONHASHSEED=1 python "$RUN/05_gap_preparation/audit/match_audit.py" "$RUN" canonical 1
```

The serial `condense` command may take substantial time. Inspect its failed rows
and confirm 4944 valid descriptions before grouping; an interrupted or failed
run is not a complete dataset. The local execution used a per-material timeout
and retry wrapper to schedule the same condenser. The wrapper's old historical
1354-group assertion intentionally failed on this environment; it is not the
recommended unattended completion script.

Export both branches with explicit size cutoffs:

```bash
for branch in binary ternary; do
  if [ "$branch" = binary ]; then limit=30; else limit=45; fi
  out="$RUN/05_gap_preparation/$branch"
  mkdir -p "$out"
  ss-screen gap-export --groups "$RUN/05_gap_preparation/audit/canonical-1-$branch-groups.json" \
    --dataset "$RUN/01_dataset/mp.df" --method external-method-pending-v1 \
    --max-natoms "$limit" --structure-dir "$out/structures" \
    --structure-format json --structure-format cif --structure-format poscar \
    --results-template "$out/gap_results_template.csv" \
    --method-metadata-template "$out/method_metadata_template.json" --output "$out/gap_tasks.csv"
done
```

These commands export pending calculation tasks, not new mBJ results. For existing
mBJ results, use the independent replay route above. No VASP calculation is implied.

## 5. Known reproducibility limits and evidence

| Checkpoint | Local November run | Historical September run |
|---|---:|---:|
| Raw records / stability prefilter | 155361 / 46675 | same |
| Unique binary / ternary composition candidates | 1759 / 3189 | same |
| Valid descriptors after four exclusions | 4944 | same |
| Binary groups / members | 491 / 1032 | same |
| Ternary groups / members | 1358 / 2041 | 1354 / 2036 |
| Final binary / ternary tasks | 949 / 1995 | same material IDs |

Five extra ternary materials all exceeded the 45-atom cutoff and were excluded.
Final material membership agrees. Full JSON hashes/task IDs do not all agree:
2930 structures have identical diagnostic primary fields; 14 passed periodic
geometry alignment at the tested precision, including six orthogonal reflections.
This is not evidence of byte-identical files or identical intermediate groups.
The historical full dependency inventory is unavailable; never label the new
constraints as that missing historical inventory.

Both historical and local grouping routes using the mBJ results produced the same
318 pairs and 317 endpoints, with normalized group/pair membership and gap values
matching within 1e-12 eV. For bitwise historical input reuse, deliver the original
frozen descriptors/groups as an optional evidence pack rather than inventing them.

## 6. Optional stability continuation and GUI boundary

MACE is not needed to screen MP records or replay the 318 pairs. To continue,
deliver the exact 79,462,305-byte MACE-MPA-0-medium checkpoint with SHA
`75428afe3a1d7d8062e19bcaabd5c433623cabf308242ec9fb493e38604fb638`
and use the separate MLP environment. Our first-ten test used random substitution
(not correlation-optimized SQS), B=0.5, 2×2×2, seed 0; FIRE/full-cell/float64,
fmax=0.01 eV/Å and 500 steps. All 27 relaxations and 10 mixing-enthalpy rows passed.

The later 3822-task phonon run was **stopped at the user's request after 40 force
tasks**. No complete phonon, competing-phase relaxation, hull or recommendation
result exists for this batch. Partial task files are not a finished result pack.
Use explicit commands and separate output directories for any future computation.

Cloning the repository does not reproduce the machine-specific MP result-viewer
adapter or auto-populate its sidebar. The portable mBJ bundle and CLI outputs are
the validated exchange interface. General GUI use requires selecting the correct
data/output paths and WSL environment on the recipient's machine.

## 7. PR and release checklist

- Review source changes, environment constraints, this guide and asset checksums.
- Run focused tests and report missing optional dependencies/fixtures honestly.
- Verify fresh-environment installation on the recipient's platform before claiming
  universal or fully offline reproducibility; current observations do not prove it.
- Supply dataset/result downloads separately; a public code repository does not
  make private external artifacts accessible automatically.
- Before PR merge, recipients must check out the PR head; after merge, use its
  recorded merge commit. PR creation alone does not publish data or deploy a GUI.
